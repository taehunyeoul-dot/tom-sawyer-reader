# 작업: "정밀 확인" 항목 만들기 — 대충 읽으면 반드시 걸리도록

한국인 중급 영어 학습자(토익 600~800)가 톰 소여의 모험을 읽고 있습니다.
이 학습자의 가장 큰 고민은 **"내가 제대로 해석한 건지, 그냥 내용을 유추한 건지 모르겠다"** 입니다.

사람은 아는 단어 몇 개와 배경지식만으로 그럴듯한 이야기를 만들어 낼 수 있고,
그렇게 만든 해석은 본인에게 매우 그럴듯하게 느껴집니다. 그래서 정답 번역을 보고도
"어, 나도 그렇게 이해했는데" 하고 넘어가 버립니다.

당신이 만들 것은 **그 얼버무림을 불가능하게 만드는 확인 항목**입니다.

## 학습자가 겪을 흐름

1. 영어 문장을 봅니다
2. **자기 손으로 한국어 번역을 씁니다** (여기서 모든 요소를 확정해야 합니다)
3. 그다음 당신이 만든 **확인 항목**을 하나씩 열어 자기 번역과 대조합니다
4. 마지막에 튜터 번역 전문을 봅니다

## 핵심 원칙

- 항목의 답은 **하나로 정해져야** 합니다. "잘 이해했나요?" 같은 건 절대 안 됩니다.
- 학습자가 **자기가 쓴 번역을 보고 O/X를 스스로 판정할 수 있어야** 합니다.
- **대충 읽으면 틀리는 지점**을 골라야 합니다. 뻔한 것은 넣지 마세요.
  (예: "Tom이 나오나요?" ← 무의미. "그 he 는 Tom 인가요 Huck 인가요?" ← 좋음)

## 자주 조용히 틀리는 다섯 가지 — 여기서 고르세요

| 코드 | 무엇을 확인하나 | 질문 예 |
|---|---|---|
| `neg` | 부정어를 놓쳤는가 (뜻이 정반대가 됨) | "이 문장은 그가 ~했다는 뜻입니까, ~하지 않았다는 뜻입니까?" |
| `who` | 행동한 주체를 잘못 잡았는가 | "창문을 연 사람은 누구입니까?" |
| `pron` | 대명사가 가리키는 것을 잘못 짚었는가 | "여기서 `them` 은 무엇을 가리킵니까?" |
| `mod` | 수식 대상을 잘못 붙였는가 | "`standing on the fence` 는 누구를 꾸밉니까?" |
| `time` | 시간 순서·시제를 놓쳤는가 | "이 일은 그가 도착하기 전입니까, 후입니까?" |

## 입력

`in_NN.json` — 그 장의 문장 22개.
```json
[{"id":"1.6.1","en":"…영어 원문…","s":"주어","v":"동사","ko":"…튜터 번역…",
  "chunks":[{"en":"…","ko":"…","r":"주어"}, …]}, …]
```

## 출력: `out_NN.json`

**모든 문장**에 대해 한 항목씩. 문장마다 확인 항목 **2~4개** (그 문장에서 정말로 헷갈릴 만한 것만).

```json
{
  "1.6.1": [
    {"t":"pron","q":"이 문장의 <b>them</b> 은 무엇을 가리킵니까?",
     "a":"안경(her spectacles)","tip":"바로 앞 문장에서 폴리 이모가 내려 쓴 그 안경입니다. 사람으로 착각하기 쉽습니다."},
    {"t":"neg","q":"이모는 그 안경으로 실제로 <b>잘 보였습니까?</b>",
     "a":"아니요 — 보라고 만든 게 아니라 '멋'을 위한 것이라 잘 보이지 않았습니다","tip":"not service 를 놓치면 정반대로 읽힙니다."}
  ],
  …
}
```

- `t` : 위 표의 코드 다섯 중 하나
- `q` : 학습자에게 묻는 말. 한국어. 짚어야 할 영어 표현은 `<b>` 로 감싸세요.
- `a` : **답이 하나로 정해진** 짧은 답. 학습자가 자기 번역과 대조할 수 있게 구체적으로.
- `tip` : 왜 여기서 틀리기 쉬운지 한 줄. (없으면 생략 가능)

## 하지 말 것

- 영어 예문을 새로 지어내지 마세요. 주어진 문장만 다룹니다.
- 답이 애매하거나 여러 개일 수 있는 질문은 넣지 마세요.
- 그 문장에 해당 사항이 없는 코드를 억지로 만들지 마세요 (부정어가 없으면 `neg` 를 넣지 않습니다).
- 문장이 짧고 단순해 헷갈릴 게 없으면 항목 2개로 충분합니다.

유효한 JSON, UTF-8, 마크다운 코드펜스 없이 JSON만 저장. 최종 응답은 `done` 한 줄만.
