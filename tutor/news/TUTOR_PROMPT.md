# 작업: NASA 기사 한 건 — 튜터 분석 + 정밀 확인 만들기

한국인 중급 영어 학습자(토익 600~800)가 이 기사를 읽습니다.
약점은 **① 어휘 부족 ② 긴 문장의 구조 파악**, 그리고
**③ "내가 제대로 해석한 건지, 그냥 유추한 건지 모르겠다"** 는 불안입니다.

기사는 소설과 달리 **짧고 완결된 글**입니다. 학습자는 이 기사 하나를 붙잡고
끝까지 정확히 읽어 보려고 합니다. 그래서 뽑아 준 문장은 빠짐없이 다뤄야 합니다.

기사는 현대 표준 영어입니다. 사투리·옛말은 없지만 대신
**긴 명사구, 수동태, 동격, 기관·계획 이름, 단위와 숫자**가 어렵습니다.

## 입력 (`tutor/news/work/`)

- `art_<기사id>.txt` — 기사 전문. 문장마다 `[문단.문장]` 번호가 붙어 있습니다.
- `in_<기사id>.json` — **다뤄야 할 문장 목록**. 형식:
  ```json
  [{"id":"626f4575|0.0","en":"…원문…","auto_s":"기계가 찾은 주어","auto_v":"기계가 찾은 동사"}]
  ```
  `auto_s`·`auto_v` 는 컴퓨터가 붙인 것이라 **틀릴 수 있습니다.** 참고만 하고 직접 판단하세요.

## 출력 1 — `tutor/news/an_<기사id>.json` (배열)

`in_*.json` 의 **모든 문장**에 하나씩. 형식:

```json
[{
  "id": "626f4575|0.0",
  "en": "<원문 그대로. 글자 하나도 바꾸지 말 것>",
  "s": "<주절의 주어 — 문장 안의 연속된 글자열 그대로>",
  "v": "<주절의 동사 — 연속된 글자열. 조동사 포함 가능 (was painted, has been)>",
  "chunks": [
    {"en": "<의미 단위 (원문 그대로)>", "ko": "<이 덩어리의 뜻>",
     "r": "<역할: 주어 / 동사 / 목적어 / 보어 / 전치사구(장소) / 시간 / 목적 / 분사구문 / 관계절(앞 명사 설명) / 동격 / 부사절(이유) / 대등절 등 짧게>"}
  ],
  "ko": "<자연스러운 한국어 전체 번역>",
  "why": "<이 문장이 왜 어려운지, 어떻게 읽어야 하는지 1~2문장. 문법 용어를 쓰면 쉬운 말을 괄호로 덧붙일 것>",
  "st": []
}]
```

**프로그램이 자동 검증하는 것 — 어기면 경고가 납니다**

1. `chunks[].en` 을 순서대로 **공백 한 칸으로 이어 붙이면 `en` 과 정확히 같아야** 합니다.
   빠짐없이, 겹침 없이, 순서대로 자르세요. 문장부호도 어느 한 덩어리에 반드시 넣으세요.
   **저장 전에 직접 이어 붙여 대조해 보세요.**
2. 덩어리는 3~10단어 정도. 앞에서부터 순서대로 읽어 내려가며(직독직해) 이해할 크기.
   1단어짜리로 잘게 자르지 마세요.
3. `s`, `v` 는 문장에 **실제로 있는 연속 글자열**이어야 합니다. 주어가 없으면 `s`="".
4. `st` 는 **항상 빈 배열** `[]` 로 두세요 (소설 전용 항목입니다).
5. `ko` 는 뜻이 정확한 것이 최우선. 원문에 없는 내용을 넣지 마세요.
   기관·계획 이름(NASA, MAX POWER 등)은 원문 표기를 살리고 필요하면 괄호로 풀어 주세요.

## 출력 2 — `tutor/news/ck_<기사id>.json` (객체)

같은 문장들에 대한 **정밀 확인 항목**입니다.

학습자는 이렇게 씁니다: ① 영어 문장을 본다 → ② **자기 손으로 한국어 번역을 쓴다**
→ ③ 당신이 만든 항목을 하나씩 열어 자기 번역과 대조한다 → ④ 튜터 번역 전문을 본다.

**얼버무림을 불가능하게 만드는 것이 목적입니다.** 사람은 아는 단어 몇 개와 배경지식으로
그럴듯한 이야기를 만들어 내고, 정답을 보고도 "나도 그렇게 이해했는데" 하고 넘어갑니다.

```json
{
  "626f4575|0.0": [
    {"t":"who","q":"칠해진 것은 무엇이고, <b>칠한</b> 쪽은 문장에 나옵니까?",
     "a":"칠해진 것은 NASA의 737 항공기입니다. 칠한 주체는 문장에 나오지 않습니다(수동태)",
     "tip":"was painted 는 '~를 칠했다'가 아니라 '칠해졌다'입니다. 주어를 행위자로 읽으면 뒤집힙니다."}
  ]
}
```

- 문장 하나당 **2~4개**. 그 문장에서 정말 헷갈릴 만한 것만.
- `t` 는 반드시 다섯 중 하나. **다른 값을 쓰면 프로그램이 버립니다.**

| 코드 | 무엇을 확인하나 |
|---|---|
| `neg` | 부정어를 놓쳤는가 (뜻이 정반대가 됨) |
| `who` | 행동한 주체를 잘못 잡았는가 — **기사에는 수동태가 많아 여기가 특히 잘 틀립니다** |
| `pron` | 대명사(it, they, this, the latter…)가 가리키는 것을 잘못 짚었는가 |
| `mod` | 수식 대상을 잘못 붙였는가 — **긴 명사구·동격이 잦아 여기도 자주 틀립니다** |
| `time` | 시간 순서·시제를 놓쳤는가 (계획 중인가 이미 한 것인가) |

- `a` 는 **답이 하나로 정해진** 짧은 답. 학습자가 자기 번역과 대조해 스스로 O/X를 낼 수 있게.
- `tip` 은 왜 여기서 틀리기 쉬운지 한 줄 (없으면 빈 문자열).
- `q` 안에서 짚어야 할 영어 표현은 `<b>` 로 감싸세요.
  **`<b>` 안의 영어는 원문에 글자 그대로 있어야 합니다** (줄일 때만 `…` 사용). 프로그램이 대조합니다.

## 하지 말 것

- 영어를 새로 지어내거나 고쳐 쓰지 마세요. 주어진 문장만 다룹니다.
- 답이 애매하거나 여러 개일 수 있는 질문을 넣지 마세요.
- 그 문장에 해당 없는 코드를 억지로 만들지 마세요 (부정어가 없으면 `neg` 를 넣지 않습니다).
- "잘 이해했나요?" 같은 항목은 절대 안 됩니다.

두 파일 모두 UTF-8, 마크다운 코드펜스 없이 순수 JSON.
최종 응답은 `done <기사id> (N문장 M항목)` 한 줄만.
